🔎anomaly-detection-fraud

Feedforward Autoencoder  ·  Credit Card Fraud Detection  ·  MLOps Example

◈Overview & Monorepo Context

anomaly-detection-fraud is a Python package that detects fraudulent credit-card transactions using a feedforward autoencoder trained from scratch with NumPy. The package lives inside the broader feedforward monorepo at apps/neural-networks/feedforward/, alongside three sibling apps: classification-email-spam, regression-house-price, and pattern-recognition-digits.

Its role in the monorepo is to demonstrate unsupervised anomaly detection: rather than learning to classify fraud directly, the model learns to reconstruct normal (legitimate) transactions. At inference time, high reconstruction error flags a transaction as anomalous.

∫The Mathematical Foundation

Task type: Unsupervised anomaly detection via reconstruction error.
Architecture: Input → Bottleneck (Hidden) → Output (same dim as Input).

1. Encoder / Decoder Forward Pass

z_enc = σ(W₁ · x + b₁)  (encoder, bottleneck)
x̂ = W₂ · z_enc + b₂  (decoder, linear output)

Here σ is the element-wise hidden activation (ReLU by default). The decoder layer is intentionally linear so the bottleneck must compress all information into a low-dimensional code.

2. Loss Function

L = MSE(x, x̂) + λ · (‖W₁‖² + ‖W₂‖²)
MSE(x, x̂) = (1/n) · Σᵢ ‖xᵢ − x̂ᵢ‖²

MSE measures reconstruction fidelity. L2 regularization (weight-decay λ) penalises large weights, preventing the degenerate identity-mapping solution where W₂ = I and W₁ = I⁻¹. λ = 0.0001 by default.

3. Anomaly Threshold

τ = percentile( { MSE(x⁽ⁱ⁾, x̂⁽ⁱ⁾) } , p )

After training on normal transactions only, the per-sample reconstruction errors are computed on the training set. The threshold_percentile (default 95 %) becomes the decision boundary. Transactions with reconstruction error > τ are flagged as fraud.

4. Backpropagation Gradients

∂L/∂x̂ᵢ = 2/n · (x̂ᵢ − xᵢ) + 2λW₂
∂L/∂W₂ = z_encᵀ · ∂L/∂x̂ᵢ + 2λW₂
∂L/∂W₁ = xᵀ · (∂L/∂x̂ᵢ · W₂ᵀ ⊙ σ′(z₁)) + 2λW₁

The chain rule flows backwards from the reconstruction error through the linear decoder, then through the non-linear encoder. Element-wise multiplication ⊙ uses the ReLU derivative (1 if z>0 else 0).

5. Why an Autoencoder?

Fraud is rare and its distribution shifts over time. Supervised classifiers over-fit to known fraud patterns. An autoencoder trained only on normal data generalises better because any deviation from normal — including unseen fraud types — produces a high reconstruction error.

Design Constraints & Patterns

  • Normal-only training: The train split contains only y == 0 samples. Fraud samples are reserved for test-time evaluation.
  • Batch gradient descent: Full-batch updates (not mini-batch), keeping the NumPy implementation simple and deterministic.
  • Early stopping: Training halts if the loss change over 100 epochs drops below 1e-7.
  • Global mutable state in API: _model, _metrics, _reference_data are module-level globals initialised once at startup via FastAPI's lifespan context manager.
  • Resilient model loading: _load_model() cascades through registry, direct NPZ path, bundled fallback, and finally trains an in-memory baseline if nothing is found.

🔬Detailed Code Walkthrough

model.py — FraudDetectionAutoencoder

The class is a @dataclass so hyperparameters are declared inline with defaults. Learned weights are stored as plain np.ndarray fields initialised to None.

Weight Initialisation

def _he_init(self, n_in, n_out, rng):
    # He init: variance = 2/n_in — stabilises ReLU gradients
    return rng.normal(0, np.sqrt(2.0 / n_in), (n_in, n_out))

def _xavier_init(self, n_in, n_out, rng):
    # Xavier init: variance = 1/n_in — suited for tanh / linear
    return rng.normal(0, np.sqrt(1.0 / n_in), (n_in, n_out))

He initialisation is chosen when the hidden activation is ReLU because it preserves gradient variance through the layer. Xavier is used for tanh. W2 (decoder) always uses Xavier because the output layer is linear.

Forward Pass

def _forward(self, X):
    z1 = np.dot(X, self.W1) + self.b1          # linear encoder
    a1 = _relu(z1) if self.hidden_activation == "relu" else _tanh(z1)
    z2 = np.dot(a1, self.W2) + self.b2          # linear decoder
    return z2, a1, z1

Only the reconstruction z2 is returned to the caller. a1 and z1 are cached because they are needed again in backpropagation.

Training Loop & Backpropagation

for epoch in range(self.n_iterations):
    recon, a1, z1 = self._forward(X_norm)
    loss = _mse_loss(X_norm, recon)
    loss += self.weight_decay * (np.sum(self.W1**2) + np.sum(self.W2**2))

    # Backprop
    dz2 = 2 * (recon - X_norm) / m
    dW2 = np.dot(a1.T, dz2) + self.weight_decay * self.W2
    db2 = np.sum(dz2, axis=0)

    da1 = np.dot(dz2, self.W2.T)
    dz1 = da1 * _relu_derivative(z1)  # element-wise gate

    dW1 = np.dot(X_norm.T, dz1) + self.weight_decay * self.W1
    db1 = np.sum(dz1, axis=0)

    # Gradient descent
    self.W1 -= self.learning_rate * dW1
    ...

Note that the gradient dz2 = 2·(recon − X)/m comes directly from differentiating MSE. L2 gradients are the weights themselves scaled by λ, added to the data-fitting gradients.

Threshold Computation

def _compute_threshold(self, X_norm):
    errors = self.reconstruction_error_normalized(X_norm)
    self.threshold = float(np.percentile(errors, self.threshold_percentile))

The threshold is a single scalar, not learned from labelled fraud. This makes the model robust to class imbalance because no fraud labels are required at training time.

train.py — Pipeline

# Train only on normal transactions — fraud is reserved for test evaluation
X_normal = X_full[y_full == 0]
X_train = X_normal[~val_mask]
X_val   = X_normal[val_mask]

model.fit(X_train, X_val=X_val, X_test=X_test, y_test=y_test)
test_metrics = model.evaluate(X_test, y_test)

The data split deliberately excludes fraud from training. X_test is balanced (equal normal and fraud samples) so that accuracy / precision / recall on the test set are meaningful.

api.py — FastAPI Lifecycle

@asynccontextmanager
async def lifespan(app: FastAPI):
    global _model, _model_version, _metrics, _drift_detector, _reference_data
    setup_logging(os.getenv("LOG_LEVEL", "INFO"))
    _metrics = MetricsCollector("credit_card_fraud_detection", port=METRICS_PORT)

The lifespan context manager replaces the deprecated @app.on_event pattern. Model, metrics collector, drift detector, and reference data are all initialised at startup, before any prediction request arrives. /reload re-executes _load_model() without restarting the container.

data.py — Synthetic Data

Two generators create realistic fraud patterns:

  • _generate_normal_transactions — low risk scores, daytime hours, small distances, low online ratio.
  • _generate_fraud_transactions — high amounts, high risk scores, late-night hours, online / foreign, high device & IP risk.

Each feature is sampled from a range that mimics real-world distributions. For example, normal transactions have merchant_risk_score ~ U[0.1, 0.4] while fraud has U[0.6, 0.95]. This inductive bias makes the autoencoder's job learnable even with limited data.

Python — Train Programmatically

from pathlib import Path
from anomaly_detection_fraud.data import generate_synthetic_data
from anomaly_detection_fraud.model import FraudDetectionAutoencoder

X, y = generate_synthetic_data(n_samples=2000, random_seed=42)
X_normal = X[y == 0]

model = FraudDetectionAutoencoder(
    hidden_dim=8,
    learning_rate=0.001,
    n_iterations=2000,
    threshold_percentile=95.0,
    weight_decay=0.0001,
)
model.fit(X_normal)
model.save("./fraud_model.npz")

Python — Predict

import numpy as np

model = FraudDetectionAutoencoder.load("./fraud_model.npz")

transaction = np.array([[
    120.0,   # time_since_last_transaction
    4500.0,  # transaction_amount (large — suspicious)
    3.0,     # merchant_category
    0.85,    # merchant_risk_score
    0.7,     # cardholder_risk_score
    200.0,   # distance_from_home
    1.0,     # is_online
    1.0,     # is_foreign
    2.0,     # hour_of_day (late night)
    5.0,     # day_of_week
    5.0,     # account_age_days
    30.0,    # recent_transaction_count
    3000.0,  # avg_transaction_amount_24h
    0.9,     # device_risk_score
    0.8,     # ip_risk_score
]])

is_fraud = model.is_fraud(transaction)[0]
error = model.reconstruction_error(transaction)[0]
proba = model.predict_proba(transaction)[0]
print(f"fraud={is_fraud}  error={error:.4f}  proba={proba:.4f}")
# Expected: fraud=True, error > threshold

📊Benchmarks

Run pytest tests/ from the app root. Key metrics produced by model.evaluate():

  • accuracy — overall classification accuracy on the balanced test set.
  • precision — of flagged transactions, fraction that are truly fraud.
  • recall — of all fraud transactions, fraction correctly flagged.
  • f1 — harmonic mean of precision and recall.
  • false_positive_rate — fraction of legitimate transactions incorrectly flagged.

The model is registered to ModelRegistry (local filesystem) and optionally to MLflow with all metrics, parameters, and artifacts (model NPZ + training chart + CSV).
