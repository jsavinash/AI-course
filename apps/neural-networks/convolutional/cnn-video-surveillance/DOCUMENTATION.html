📋 Overview & Monorepo Context

Name, purpose, role, and dependencies within the broader monorepo.

Package Identity

  • Package name: video-surveillance
  • Module: cnn_video_surveillance
  • Version: 0.1.0
  • Description: Tracks crowd movement and spots security threats in real-time frame images — CNN MLOps example.

Monorepo Role

The third CNN-family app under apps/neural-networks/convolutional/, alongside cnn-medical-imaging and cnn-facial-recognition. It shares the identical training pipeline and serving architecture, differing only in the 3-class label schema (normal, activity, threat) and the FastAPI metrics port (8018).

Key Dependencies

  • ai-core — shared workspace (logging, registry, drift, validation, metrics)
  • numpy >= 1.26.0 — all numerical computation
  • fastapi + uvicorn — HTTP serving
  • pydantic >= 2.6.0 — request/response validation
  • prometheus-client — metrics exposition
  • matplotlib — training-loss charting

Output Contract

  • Task type: Multi-class classification (3 classes: normal, activity, threat)
  • Input shape: (N, 1, 8, 8) — 8×8 grayscale pixel arrays, 64 features
  • Output: Argmax of softmax probability vector
  • Loss: Categorical cross-entropy
  • Framework: Pure NumPy

∫ The Mathematical Foundation

CNN equations identical to cnn-medical-imaging — full derivations are covered there. This section highlights the class-implication differences.

E1 $$Z^{(l)} = W^{(l)} * X^{(l)} + b^{(l)}$$
E2 $$A^{(l)} = \text{ReLU}\!\left(Z^{(l)}\right) = \max(0, Z^{(l)})$$
E3 $$\text{Softmax}(z)_j = \frac{e^{z_j}}{\sum_{k=1}^{3} e^{z_k}}$$
K=3 activity classes. The argmax prediction maps 0→normal, 1→activity, 2→threat.
E4 $$\mathcal{L}_{CE} = -\sum_{i=1}^{3} y_i \log(\hat{y}_i)$$

Shared Architecture Rationale

All three CNN apps use the identical SimpleCNN hyperparameters (8 filters, 3×3 kernel, 32 hidden units, 300 epochs). This pedagogical uniform-architecture choice lets students compare task outcomes while holding model capacity constant.

3-Class Softmax vs. Sigmoid

Surveillance requires mutually-exclusive multi-class output (a frame can be normal or an activity or a threat, never more than one). Softmax enforces the probability simplex constraint Σℓp&subi; = 1.

Drift Detection Relevance

Real-world surveillance footage distribution shifts over time (lighting changes, camera angles, scene layout). The PSI-based DriftDetector (threshold 0.2) alerts operators when input pixel distributions diverge from the training reference — a critical MLOps feature for production video pipelines.

Metrics Port Isolation

Port 8018 is reserved for this service's Prometheus exposition, avoiding collisions with the other CNN apps (8016, 8017) in the same deployment environment.

📝 Detailed Code Walkthrough

Deep dive into the key files, classes, and functions.

model.py — VideoSurveillanceCNN (lines 19–152)

Structurally identical to MedicalImagingCNN: same @dataclass fields, same SimpleCNN wrapper, same fit/predict/evaluate/save/load interface. The only semantic difference is output_dim=3, which triggers the one-hot encoding branch in fit().

@dataclass
class VideoSurveillanceCNN:
    IMG_SIZE: int = 8; N_CHANNELS: int = 1
    n_filters: int = 8; kernel_size: int = 3; hidden_dim: int = 32
    output_dim: int = 3        # 3 activity classes
    learning_rate: float = 0.05; n_iterations: int = 300
    weight_decay: float = 0.001; clip_value: float = 5.0
    random_seed: int = 42
    model: SimpleCNN | None = None
    training_mode: str = "supervised"
    loss_history: list[float] = field(default_factory=list)

train.py — Pipeline (lines 21–208)

Identical to the medical-imaging train.py with these class-specific substitutions:

  • create_video_surveillance_schema() — validator function
  • VideoSurveillanceCNN — model class
  • model_name="video-surveillance" — registry key
  • video_surveillance_model_v{version}.npz — artifact filename

api.py — Prediction Endpoint (lines 545–603)

The _compute_prediction() function uses np.argmax(probas) to select the activity class. The activity field in the response is cast to str(pred_idx) for JSON serialisation consistency. The drift detector accumulates raw input vectors in _recent_predictions up to 1000 entries for downstream PSI analysis.

▶️ Examples & Usage

Train via CLI

uv run python -m cnn_video_surveillance.train \
  --model-dir ./artifacts/models \
  --n-samples 1000 \
  --n-filters 16 \
  --n-iterations 500 \
  --learning-rate 0.03 \
  --register-mlflow

Train Programmatically

from cnn_video_surveillance.model import VideoSurveillanceCNN
from cnn_video_surveillance.data import generate_synthetic_data, train_test_split

X, y = generate_synthetic_data(n_samples=500, random_seed=42)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_seed=42)

model = VideoSurveillanceCNN(
    n_filters=16, hidden_dim=64,
    learning_rate=0.03, n_iterations=500,
)
model.fit(X_train, y_train, X_val=X_test, y_val=y_test)
print(model.evaluate(X_test, y_test))
model.save("./artifacts/video_surveillance_v2.npz")

Predict — Single Frame

import numpy as np
from cnn_video_surveillance.model import VideoSurveillanceCNN

model = VideoSurveillanceCNN.load("./artifacts/video_surveillance_v2.npz")
sample = np.random.rand(64).astype(np.float32)
pred_idx = model.predict(sample.reshape(1, -1))[0]
labels = ['normal', 'activity', 'threat']
print(f"Detected: {labels[pred_idx]}")
