1. Overview & Monorepo Context

Name, purpose, and role within the broader monorepo.

Package name: recommendation-engine
Version: 0.1.0
Purpose: Mine association rules from transaction data using the Apriori algorithm and generate product recommendations. Given a user's basket, the model returns items likely to be purchased together, scored by lift, confidence, and support.

Monorepo role: Lives under unsupervised/. It depends on ai-core for logging, metrics, and model registry. Unlike the other unsupervised apps, it operates on discrete categorical transactions rather than continuous feature vectors. The API exposes /recommend, /rules, and /rules/{item} endpoints.

2. The Mathematical Foundation

Support, confidence, lift, and the Apriori principle.

$$\text{support}(X) = \frac{|X|}{\text{total transactions}}$$
$$\text{confidence}(X \Rightarrow Y) = \frac{\text{support}(X \cup Y)}{\text{support}(X)}$$
$$\text{lift}(X \Rightarrow Y) = \frac{\text{confidence}(X \Rightarrow Y)}{\text{support}(Y)}$$
$$\text{cosine}(u,v) = \frac{u \cdot v}{\|u\| \|v\|}$$

Why this math? Apriori leverages the downward closure property: all subsets of a frequent itemset must also be frequent. This allows aggressive pruning of candidate itemsets, making the algorithm tractable for moderate-sized catalogs. Lift measures how much more likely Y is given X compared to baseline; lift > 1 indicates a genuine association. The recommendation score combines lift, confidence, and support: score = lift * confidence * (1 + support).

3. Core Logic & Architecture

Data flow, design patterns, and lifecycle.

graph TD
  A[Transactions CSV] --> B[Load / Generate synthetic data]
  B --> C[Apriori.fit: find frequent itemsets]
  C --> D[Generate association rules]
  D --> E[Filter by min_confidence & min_lift]
  E --> F[ModelRegistry.save]
  F --> G[FastAPI lifespan load]
  G --> H[/recommend /rules /rules/{item}]
  H --> I[DriftDetector on one-hot matrix]

Design patterns:

  • Immutable rule objects: AssociationRule is a @dataclass(frozen=True), ensuring rules are hashable and safe to sort/filter.
  • Two-phase training: fit() first mines frequent itemsets, then generates rules. This separation makes it easy to inspect intermediate results.
  • Recommendation scoring: recommend() matches basket items against rule antecedents and ranks consequents by a composite score.
  • Drift on one-hot matrix: Recent baskets are converted to one-hot vectors and compared against reference data via PSI.

Primary execution path: train.py:main() → loads transactions → fits Apriori → evaluates coverage and average metrics → saves model → registers to ModelRegistry.

4. Detailed Code Walkthrough

Key files, classes, and functions.

model.py — Apriori & AssociationRule

@dataclass(frozen=True)
class AssociationRule:
    antecedent: frozenset[str]
    consequent: frozenset[str]
    support: float
    confidence: float
    lift: float
    conviction: float

    def to_dict(self) -> dict[str, Any]:
        return {
            "antecedent": sorted(self.antecedent),
            "consequent": sorted(self.consequent),
            "support": round(self.support, 4),
            "confidence": round(self.confidence, 4),
            "lift": round(self.lift, 4),
            "conviction": round(self.conviction, 4),
        }

def _generate_candidates(self, frequent_itemsets: list[frozenset[str]], k: int) -> set[frozenset[str]]:
    """Generate candidate itemsets of size k from frequent itemsets of size k-1."""
    candidates: set[frozenset[str]] = set()
    n = len(frequent_itemsets)
    for i in range(n):
        for j in range(i + 1, n):
            itemset1 = frequent_itemsets[i]
            itemset2 = frequent_itemsets[j]
            list1 = sorted(itemset1)
            list2 = sorted(itemset2)
            if list1[:-1] == list2[:-1]:
                new_itemset = itemset1 | itemset2
                if len(new_itemset) == k and self._has_frequent_subsets(new_itemset, frequent_itemsets):
                    candidates.add(new_itemset)
    return candidates

Why this design:

  • frozenset is used for itemsets so they are immutable and hashable (can be dict keys).
  • The candidate generation step implements the Apriori join-and-prune strategy: only combine itemsets that share k-2 prefix items and whose k-1 subsets are all frequent.
  • Rules are sorted by (lift, confidence) descending so the most actionable rules appear first.
  • conviction is included as an additional rule quality metric: (1 - support(Y)) / (1 - confidence).

5. Examples & Usage

Training, serving, and consuming the API.

CLI Training

uv run python -m recommendation_engine.train --model-dir ./artifacts/models --min-support 0.05 --min-confidence 0.5 --min-lift 1.0

Python Usage

from recommendation_engine.model import Apriori

transactions = [
    ["Bread", "Milk", "Butter"],
    ["Beer", "Diapers", "Chips"],
    ["Bread", "Milk"],
    ["Beer", "Diapers"],
]

model = Apriori(min_support=0.05, min_confidence=0.5, min_lift=1.0, max_itemset_size=4)
model.fit(transactions)

recs = model.recommend(items=["Bread", "Milk"], top_k=5)
for r in recs:
    print(f"{r['item']}: score={r['score']}, lift={r['lift']}, confidence={r['confidence']}")

REST API Requests

curl -X POST http://localhost:8004/recommend \
  -H "Content-Type: application/json" \

    "top_k": 5,
    "exclude_purchased": true
  }'
