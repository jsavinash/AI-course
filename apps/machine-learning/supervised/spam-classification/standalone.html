1. Overview & Monorepo Context

Name, purpose, and role within the broader monorepo.

Package name: spam-classification
Version: 0.2.0
Purpose: Classify emails as SPAM or NOT spam using a from-scratch logistic regression model. Five binary features are extracted from raw email text (free, win, link, !!!, meeting), and the model is trained via gradient descent on binary cross-entropy loss.

Monorepo role: Lives under supervised/ alongside pizza-price. It depends on ai-core for shared infrastructure (logging, validation, metrics, model registry, drift detection). The API layer adds a /predict/email endpoint that auto-extracts features from raw text, differentiating it from the pizza-price regression API.

2. The Mathematical Foundation

Logistic regression, sigmoid, and binary cross-entropy.

$$z = w \cdot x + b$$
$$\hat{y} = \sigma(z) = \frac{1}{1 + e^{-z}}$$
$$\mathcal{L}_{BCE} = -\frac{1}{n} \sum_{i=1}^{n} [y_i \log(\hat{y}_i) + (1-y_i)\log(1-\hat{y}_i)]$$
$$\frac{\partial \mathcal{L}}{\partial w} = \frac{1}{n} \sum_{i=1}^{n} (\hat{y}_i - y_i)x_i$$
$$\frac{\partial \mathcal{L}}{\partial b} = \frac{1}{n} \sum_{i=1}^{n} (\hat{y}_i - y_i)$$

Why this math? Logistic regression models P(y=1|x) via the sigmoid function, producing outputs in [0,1]. Binary cross-entropy penalizes confident wrong predictions exponentially. The gradient simplifies to (ŷ - y)x, enabling efficient SGD. A 1e-9 epsilon is added inside log to avoid log(0) numerical instability.

Data flow, design patterns, and lifecycle.

Design patterns:

  • Feature extraction layer: extract_features() converts raw text into the 5 binary features the model expects, enabling both structured and unstructured inputs.
  • Shared prediction logic: _compute_prediction() centralizes validation, inference, metrics, and drift tracking for both /predict and /predict/email.
  • Resilient model loading: Same four-tier fallback as pizza-price (registry → direct → bundled → baseline).
  • Drift on binary features: PSI is computed over the 5 binary feature vectors to detect concept drift in spam patterns.

Primary execution path (training): train.py:main() parses CLI args → loads labeled data → validates → splits → fits logistic regression → evaluates accuracy/precision/recall/F1/ROC-AUC → saves artifacts → registers model.

4. Detailed Code Walkthrough

Key files, classes, and functions.

model.py — LogisticRegression

@dataclass
class LogisticRegression:
    learning_rate: float = 0.1
    n_iterations: int = 2000
    weights: np.ndarray | None = None
    bias: float = 0.0
    loss_history: list[float] = field(default_factory=list)

    def _sigmoid(self, z: np.ndarray) -> np.ndarray:
        """Sigmoid activation with numerical stability."""
        z = np.clip(z, -500, 500)          # Prevent overflow in exp
        return 1 / (1 + np.exp(-z))

    def fit(self, X: np.ndarray, y: np.ndarray) -> "LogisticRegression":
        n_samples, n_features = X.shape
        self.weights = np.zeros(n_features)
        self.bias = 0.0

        for _ in range(self.n_iterations):
            probs = self.predict_proba(X)
            loss = -np.mean(y * np.log(probs + 1e-9) + (1 - y) * np.log(1 - probs + 1e-9))
            self.loss_history.append(float(loss))

            dw = (1 / n_samples) * np.dot(X.T, (probs - y))
            db = (1 / n_samples) * np.sum(probs - y)

            self.weights -= self.learning_rate * dw
            self.bias -= self.learning_rate * db
        return self

Why this design:

  • np.clip(z, -500, 500) prevents exp overflow for large magnitude inputs.
  • The 1e-9 epsilon inside log prevents log(0) when probabilities are exactly 0 or 1.
  • Gradient dw = (1/n) X^T (ŷ - y) is the vectorized form of the BCE derivative, much faster than looping over samples.
  • Metrics include ROC-AUC computed via ranking (no external sklearn dependency).

api.py — Feature Extraction & Dual Endpoints

def extract_features(text: str) -> list[int]:
    """Extract 5 binary features from raw email text."""
    text_lower = text.lower()
    return [
        1 if "free" in text_lower else 0,
        1 if re.search(r"\bwin\b", text_lower) else 0,
        1 if re.search(r"https?://|www\.", text_lower) else 0,
        1 if text.count("!") >= 3 else 0,
        1 if "meeting" in text_lower else 0,
    ]

@app.post("/predict/email", response_model=PredictResponse)
def predict_email(body: EmailRequest):
    """Classify an email given raw text. Features are auto-extracted."""
    features = extract_features(body.text)
    return _compute_prediction(features, body.threshold)

5. Examples & Usage

Training, serving, and consuming the API.

CLI Training

uv run python -m spam_classification.train --model-dir ./artifacts/models --learning-rate 0.1 --n-iterations 2000

Python Usage

from spam_classification.model import LogisticRegression
import numpy as np

X = np.array([[1,1,1,1,0],[0,0,0,0,1],[1,0,1,0,0]], dtype=float)
y = np.array([1, 0, 1], dtype=int)

model = LogisticRegression(learning_rate=0.1, n_iterations=2000)
model.fit(X, y)

proba = model.predict_proba(np.array([[1,0,1,1,0]]))[0]
print(f"Spam probability: {proba:.4f}")  # e.g. 0.8734

REST API Requests

# Explicit features
curl -X POST http://localhost:8002/predict \
  -H "Content-Type: application/json" \
  -d '{"features": [1,0,1,1,0], "threshold": 0.5}'

# Raw email text
curl -X POST http://localhost:8002/predict/email \
  -H "Content-Type: application/json" \
  -d '{"text": "Free win! Check http://example.com !!!", "threshold": 0.5}'
